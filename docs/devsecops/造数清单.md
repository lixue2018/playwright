# DevSecOps 造数清单（给测试人员）

扫描文件通过接口提交，**不要**指望 Playwright 自己上传包。

**对外统一上传**（推荐）：`POST …/devops/upload`（四头 AKSK 签名；现网示例见 server `docs/api/DevSecOps源码收包-对接速查.md`）  
**内网落地**：`POST /api/loophole/tabletProject/receive`  
`multipart`：`file`（可选）+ `info`（`PackageInfo` JSON）；请求头带 `X-AKSK-Access-Key-Id`（AccessKey）。

**本仓库脚本**（Git Bash）：[`scripts/devsecops/`](../../scripts/devsecops/README.md)。  
pre 默认地址 `https://admin.csl.secx/devops/upload`；一次请求一个文件；Android / iOS / Windows 拆成 3 条（不同 `packageName`）。  
快捷：`bash scripts/devsecops/seed_three.sh`（AK/SK 默认见 `scripts/devsecops/env.sh`）。

- 平板 APK / Windows：必传 `file`；`devopsType` = `tablet_android` / `tablet_ios` / `windows` 等  
- 源码：`info.devopsType=source` + `scanMode`：
  - `RESULT_ONLY`：无 file；`checkmarxScanId` / `checkmarxReportUrl` / `coverityReportUrl`
  - `SOURCE_PACKAGE`：必传源码包 `file`
  - `COVERITY`：无 file；必传 `fileJson`（多链接同次共用 `scan_batch_id`）

`info` 常用字段：`devopsType`、`packageName`/`label`、`branch`、`buildNumber`、`versionName`、`itCode`、`scanMode`、`env`、`fileJson`。

节点 location：`1` 基线 · `2` 隐私 · `3` 渗透 · `4` 源码。  
列表「待修复数」**只计漏洞状态=待修复(1)**，不含待评估(99)。

## 一、需要建的项目（建议命名前缀 `DS-`）

造完后把 **项目 ID / 应用名** 回填 `playwright/fixtures/devsecops/fixture_projects.json`。

| Fixture | 建议项目名 | 产品类型 | 目标节点态（列表可见） | 待修复数展示 | 用途 |
|---------|------------|----------|------------------------|--------------|------|
| OFF01 | DS-未开启-空项目 | Android | 四节点均为 **未开启** | `-` | 筛选未开启；详情未开启 |
| WAIT01 | DS-等待扫描 | Android | 隐私/基线至少一节点 **等待扫描** | `-` | 聚合：全等 0 |
| SCAN01 | DS-扫描中 | Android | 目标节点 **扫描中** | `-` | 扫描中优先于待审 |
| PEND01 | DS-待人工审核 | Android | **待人工审核** | 有数字或 0 | 有待处理洞、未人工改 |
| REV01 | DS-审核中 | Android | **审核中** | 有数字 | 待处理 + 后台已改过至少一条洞状态 |
| FIX01 | DS-漏洞待修复 | Android | **漏洞待修复** | **≥1**（仅待修复/待评估） | 列表 `状态(n)` |
| PASS01 | DS-扫描通过 | Android | **扫描通过** | 0 | 0 洞或全已修复/已忽略 |
| FAIL01 | DS-扫描失败 | Android | **扫描失败** | `-` | 最新一批日志全部失败 |
| STATIC01 | DS-隐私静态成功 | Android | 隐私=**静态检测成功**；基线勿跟成 6 | 隐私按规则 | 仅隐私展示 6 |
| MIX01 | DS-批次混合 | Android | 同批：一失败+一通过 → 节点 **扫描通过** | 按洞 | 验证 fail 不拖死 |
| MIX02 | DS-扫描中压待审 | Android | 同批：一扫描中 + 一待审 → **扫描中** | `-` | 优先级 |
| BRANCH01 | DS-多分支 | Android | 同项目 ≥2 个 `branch` 均有扫描日志 | 按最新批 | 多分支并存 |
| WIN01 | DS-Windows渗透无初审 | **Windows** | 渗透：**漏洞待修复** 或 **扫描通过**；**无初审** | 有洞则 ≥1 | Windows 取消初审 |
| SRC01 | DS-源码双工具 | 源码建项 | 源码节点有 CheckMarx+Coverity | 按洞 | 5202 回归 |
| SRC02 | DS-源码仅 Coverity | 源码 | Coverity 待修复/待审任选 | 按洞 | 扫描编号筛选 |
| FILTER01 | DS-跨节点筛选 | Android | 源码未开启 + 隐私待修复（或任意两节点不同态） | — | 跨节点 OR 筛选 |
| CNT01 | DS-数量展示 | Android | 任一节点待修复且数量 >0 | `状态(n)` | 导出列同格式 |
| BUSY01 | DS-忙状态拦截 | Android | 节点处于 0/7/1/2 之一 | — | 再收同批应拦截（接口/日志侧验） |

> 项目可复用：若一个 Android 包会同时打出基线+隐私+渗透日志，可用 **同一项目** 覆盖多节点，只要在 fixture 里注明「以哪一列断言」即可。上表按「断言维度」拆开，方便分工造数。

## 二、各项目需要的测试文件 / 接口参数

### 1. Android 包（隐私 / 基线 / 渗透共用）

| 文件 | 说明 | 对应项目 |
|------|------|----------|
| `ds-android-wait.apk` | 正常包；提交后保持队列未跑完或人工停在等待扫描 | WAIT01 |
| `ds-android-scan.apk` | 正常包；提交后工具侧保持扫描中 | SCAN01 |
| `ds-android-vuln-pending.apk` | 能出 **待处理** 洞的包（或出洞后勿点去处理） | PEND01 |
| `ds-android-vuln-fix.apk` | 能出 **待修复** 洞；初审完成后只留待修复 | FIX01 / CNT01 / FILTER01 |
| `ds-android-clean.apk` | 扫描完成 **0 洞** 或洞全忽略 | PASS01 |
| `ds-android-fail.apk` | 工具侧扫描失败（或 Portal 回失败 + `scan_desc`） | FAIL01 |
| `ds-android-static.apk` | 隐私：**动态失败 + 静态成功** → 日志 status=6 | STATIC01 |
| `ds-android-mix-a.apk` + `ds-android-mix-b.apk` | **同一次触发**（同一 `scan_batch_id`）：一个失败、一个通过 | MIX01 |
| `ds-android-mix-scan.apk` + 同批待审日志 | 同批一扫描中一待审 | MIX02 |
| `ds-android-branch-main.apk` | `branch=main`（或 `release/a`） | BRANCH01 |
| `ds-android-branch-dev.apk` | `branch=dev`（或 `release/b`），**同一 packageName/label** | BRANCH01 |

`info` 示例（Android）：

```json
{
  "devopsType": "tablet_android",
  "packageName": "com.lenovo.ds.fix01",
  "label": "DS-漏洞待修复",
  "branch": "main",
  "buildNumber": "DS-FIX01-1",
  "versionName": "1.0.0",
  "itCode": "fengtt1"
}
```

OFF01：**只建项目、不传任何包**（或建项后四节点均无 `sec_tablet_scan_log`）。

### 2. Windows 渗透（WIN01）

| 文件 | 说明 |
|------|------|
| `ds-windows-pen.exe` | `devopsType=windows` 或后缀 `.exe`；走渗透节点 |

期望：出洞后状态为 **待修复**（非待人工审核）；后台无 Windows 渗透初审操作（点初审应提示已取消）。

```json
  "branch": "main",
  "buildNumber": "DS-WIN01-1",
  "versionName": "1.0.0",
  "itCode": "fengtt1"
}
```

### 3. 源码（SRC01 / SRC02）

| 提交方式 | 参数 | 文件/链接 |
|----------|------|-----------|
| CheckMarx 报告 | `devopsType=source`, `scanMode=RESULT_ONLY`, `checkmarxReportUrl`, `checkmarxScanId` | 可用真实/联调报告 URL |
| Coverity 报告 | `scanMode=COVERITY` 或 RESULT_ONLY + `coverityReportUrl` / `fileJson` 多链接 | Coverity 报告链接 |
| 源码包（可选） | `scanMode=SOURCE_PACKAGE` + `file` zip/tar | `ds-source-demo.zip` |

```json
{
  "devopsType": "source",
  "scanMode": "RESULT_ONLY",
  "packageName": "DS-源码双工具",
  "label": "DS-源码双工具",
  "branch": "release/1.0.0",
  "buildNumber": "JENKINS-DS-SRC01",
  "itCode": "fengtt1",
  "checkmarxReportUrl": "https://...",
  "checkmarxScanId": "...",
  "coverityReportUrl": "https://..."
}
```

SRC01：同一扫描周期内 **两种工具都有日志**（可同一次或紧挨着两次收包，保证同 `scan_cycle` / 业务周期）。  
SRC02：仅 Coverity，便于扫「扫描编号」筛选。

## 三、造数后人工动作（接口出洞还不够时）

| Fixture | 额外操作 |
|---------|----------|
| PEND01 | 出待处理洞后 **不要** 点「去处理」 |
| REV01 | 在 PEND01 基础上后台对至少 1 条待处理洞改状态 → 节点变 **审核中** |
| FIX01 | 完成初审（非 Windows），洞落在待修复/待评估 |
| STATIC01 | 确认隐私扫描日志 `status=6`，基线不要全是 6 |
| MIX01/02 | 确认同批 `scan_batch_id` 相同 |
| WIN01 | 确认不能走初审；接口人有修复待办 |
| BUSY01 | 节点忙时再调 receive，应失败或提示忙碌 |

## 四、回填 fixture 模板

见 `fixtures/devsecops/fixture_projects.json`。最少填：

- `project_id` / `name`（应用名，列表搜索用）
