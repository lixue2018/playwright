# 4834 造数状态池与用例消耗

> **硬约束**：节点一旦进入**终态**，该节点上的中间态用例再也测不了。  
> 终态（不可再审 / 不可再改业务态）：`2` 通过、`21` 通过遗留、`101/102` 免审、`100` 不适用、`11` 已关闭。  
> **可回退**：`99` 审核暂停（恢复/重启）→ 回到中间态，**不是**终态。  
> 闸道 SSOT：[`docs/common/节点闸道规则.md`](../common/节点闸道规则.md)

---

## 1. 问题：以前造数怎么把路堵死

| 旧做法 | 后果 |
| --- | --- |
| `exempt_then_pause_ok`：先把「架构」免审，再拿「数据」做可暂停 | **架构永久烧掉**，G1 上架构的排队中/申请暂停再也测不了 |
| `advance` 把整闸道审到终态 | 该闸道所有中间态用例作废，只能测下一闸或禁态 |
| 同一节点上乱序跑：先审通过再测暂停 | 用例失败或只能 skip，数据浪费 |
| 终审关闭跑在仍要测安全节点的项目上 | **整项目锁死** |

---

## 2. 原则（用例 + 造数统一遵守）

1. **先测再终态**：某节点还要测「可申请 / 审核中 / 暂停申请」→ 禁止对该节点点通过/免审。  
2. **暂停 ≠ 终态**：`99` 留给恢复闭环；测完恢复后节点回到中间态，**仍可再申请暂停**（可复用）。  
3. **一节点一条闭环**：同一节点顺序固定  
   `可申请(FP) → 暂停审核(BP) → 已暂停(FR) → 恢复审核(BR)` →（可选）再测或最后才推进终态。  
4. **角色分池，不要共用一个「万能节点」**：不同用例要不同**当前态**；态不够就换**兄弟节点**或**新项目**，不要靠免审「挤」出下一个。  
5. **关闭单独项目**：FC/BC 只用专用项目；关闭后该项目退出状态池。  
6. **缺态就 skip + 提示造数**，禁止用例里为了跑通去免审/通过「还没测完」的节点。

## 3. 状态池（项目 × 节点角色）

最少两套项目（冒烟）；全量再加关闭专用。

| Fixture 键 | 角色 | 造数目标 | 供给用例 | 消耗后 |
| --- | --- | --- | --- | --- |
| **EM01** | `pause_ok` | 基本信息已通过；**至少一个**安全节点仍为可申请中间态；**默认不免审任何节点** | 暂停入口、FP 空理由/提交、BP、AUTH 按钮 | FP 提交后变 pending；BP 通过后变 `99` → 可接着 FR/BR **或** 换节点再测 FP |
| **EM02** | `paused` | 基本信息已通过；**指定节点**已是 `99`（与 EM01 的 pause_ok **尽量不同节点名**，少抢态） | FR 申请恢复、BR 恢复审核 | BR 通过后回中间态；节点仍可再测暂停 |
| **EM_CLOSE**（可选第三项目） | `close` | G2 已过、终审可关；或接受「测完即废」 | FC / BC | 关闭后整项目废弃 |
| （同项目内只读） | `forbid` | 已是 `103/101/2/11` 的节点 | FP-003 等禁态负向 | **只读**，不再改这些节点 |

### 闸道内节点怎么分（G1 示例，全量推荐）

| 节点 | 建议角色 | 说明 |
| --- | --- | --- |
| 架构审核 | `pause_ok` 主测 | 默认冒烟钉这里；**不要**为了开下一节点而免审它 |
| 数据安全 | `paused` 或第二轮 pause_ok | EM02 shape 可钉此节点 |
| 隐私安全 | 保留中间态 | API 矩阵 / 驳回 / 二次申请 |
| 源代码安全 | 保留或测完再终态 | 本闸最后才 `advance` |

G2 同理：开源→基线→渗透→AI→基建，**单节点闭环测完**再对「已测完」节点推终态，整闸测完才 `advance-gate g2`。

## 4. 造数命令怎么选

```bash
# 冒烟默认（推荐）：只审基本信息 + 标记 pause_ok / 置 paused，不免审烧左侧
PSRB_TEST_ENV=216 npm run prepare:4834 -- --phase all

# 全量中间态：不要 shape，停在闸道
PSRB_TEST_ENV=216 npm run prepare:4834 -- --stop-at-gate g1

# 单节点闭环：钉死节点（仍不免审兄弟节点）
PSRB_TEST_ENV=216 npm run prepare:4834 -- --focus-node 数据安全 --phase all

# 显式允许「免审左侧挤出下一节点」（旧冒烟最短，会烧节点，仅 CI 赶路）
PSRB_TEST_ENV=216 PREPARE_SACRIFICE_LEFT=1 npm run prepare:4834 -- --phase all

# 本闸用例全部勾完后，才推进闸道（不可逆）
PSRB_TEST_ENV=216 npm run prepare:4834 -- --phase advance --advance-gate g1 --em01 <pid> --em02 <pid>
```

| phase / 开关 | 是否制造终态 | 何时用 |
| --- | --- | --- |
| `create` | 否 | 新项目 |
| `approve` | 仅基本信息→通过（G0 结束） | G1 开测前 |
| `shape`（默认） | 否免审；EM02 可→`99` | 冒烟 / 补 pause_ok、paused |
| `PREPARE_SACRIFICE_LEFT=1` | **会免审**左侧 | 明确放弃该节点中间态 |
| `advance` | **整闸**推向终态 | 该闸所有中间态用例已 ☑ |
| 终审关闭 | 整项目锁 | 仅 EM_CLOSE |

## 5. 用例怎么改（执行与脚本）

### 5.1 冒烟顺序（已有 `run-smoke-node-order.js`）

```text
CFG（与节点无关）
  → EM01：入口 + FP（消耗 pause_ok → pending）
  → EM01：BP（pending → 99）
  → EM02：FR（依赖 paused）
  → EM02：BR（99 恢复）
  → EM_CLOSE：FC → BC（可选；默认 RUN_CLOSE 控制）
  → AUTH（尽量用只读/已有态，勿新免审）
```

- FP/BP 与 FR/BR **分项目**，避免一条链路把唯一节点跑穿后另一条缺态。  
- 若合并到同一项目同一节点：必须严格 FP→BP→FR→BR，且 fixture 在 BP 后把该节点标成 `paused_node`。

### 5.2 缺态策略

| 需要 | 没有时 |
| --- | --- |
| `pause_ok_node` | `test.skip` + 提示 `prepare --phase approve,shape`（**不要**在用例里免审） |
| `paused_node` / status=99 | skip；或只跑 FR 前先确认 EM02 shape |
| 禁态样本 | 优先用导航里已有 `103/101/2`；没有再单独造，**勿**把 pause_ok 节点审死来凑负向 |
| 关闭 | 独立项目；`RUN_CLOSE=0` 则 skip |

### 5.3 全量 / 缺态

- 缺 `pause_ok` / `paused`：重新 **页面** `prepare --phase approve,shape`，禁止 API 补申请。  
- 全量按闸道勾选：G1 四节点各自闭环 ☑ → 再 `advance g1` → G2 …  
- logic 用例仍可跑纯函数；**不再维护 API 用例工程**。

## 6. Fixture 字段约定

| 字段 | 含义 |
| --- | --- |
| `pause_ok_node` / `_location` | EM01 当前可申请暂停的节点 |
| `paused_node` / `_location` | EM02（或同项目）当前 `99` 节点 |
| `exempt_node` | **仅** `PREPARE_SACRIFICE_LEFT` 或显式免审时写入；表示已牺牲 |
| `node_roles` | `{ pause_ok, paused, forbid: [] }` 快照，便于人工对照 |
| `advanced_gate` | 已推进到的闸道；之后勿再对该闸测中间态 |

---

## 7. 一句话

**中间态是耗材，终态是坟墓；暂停是停车场。**  
造数默认只把车停进停车场或留在路上，除非你确认这条路已经测完，否则不要把车开进坟墓，更不要为了开下一条路把左边整条路填平。
