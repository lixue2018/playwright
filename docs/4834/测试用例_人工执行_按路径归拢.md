### 0.4 建议造数（状态池 · 终态不可逆）

至少准备（详见 [`造数状态池与用例消耗.md`](./造数状态池与用例消耗.md)）：

1. **项目 A（pause_ok）**：基本信息已通过；至少 1 个安全节点仍为可申请中间态；**不要**为开下一节点免审左侧  
2. **项目 B（paused）**：至少 1 个节点已是审核暂停（测恢复）；尽量与 A 焦点节点错开  
3. **项目 C（forbid 样本 / 可与 A 同项目只读）**：未开启 / 免审 / 已通过 等禁态对照  
4. **项目 D（close，可选）**：专测终审关闭；关闭后废弃  
5. （可选）项目级暂停规则：`autoCloseDays=90`，对照系统默认 60  

项目名建议：`4834-人工-YYYYMMDD-xx`，全程记下 **项目编号**。  
**禁止**：一上来把左侧节点全部审过；缺态时不要把还要测的节点审成终态来「凑」下一案。

### 0.5 节点闸道（必读 · 引用公共规则）

> **全项目统一**，勿在本需求再另写一套。完整定义见：
> **[`docs/common/节点闸道规则.md`](../common/节点闸道规则.md)**
> 代码：`utils/node-order.js`

摘要：

| 闸道 | 节点 | 测完后才允许 |
| --- | --- | --- |
| **G0** | 基本信息 | 基本信息**审批通过** |
| **G1** | 架构 / 数据 / 隐私 / 源码（4） | 四节点全部审到通过/免审等（本闸含前台提交+后台审核） |
| **G2** | 开源 / 基线 / 渗透 / AI / 基建（5） | 五节点全部审到通过/终态 |
| **G3** | 终审 | 才测申请关闭 |

**口诀**：先测左边 → 本闸测完再审过 → 再测右边；**一节点测完再换下一节点**。

### 0.6 推荐执行顺序（少换登录 · 单节点闭环）

```text
一、后台邮件提醒模块（jicq1 一次做完，与节点无关）
    ↓
二、按闸道 × 单节点闭环（每个节点：前台接口人 → 本节点审核人 → 再下一节点）
      G0 基本信息 整包测完 → 审过
      G1 架构 → 数据 → 隐私 → 源码（每节点整包测完再换；全员测完再统一审过）
      G2 开源 → 基线 → 渗透 → AI → 基建（同上）
      G3 终审关闭
    ↓
三、自动发邮件 / 自动暂停 / 自动关闭（调度类，最后集中）
```

#### 单节点闭环清单（同一节点连续做，再换节点）

| 顺序 | 登录 | 做什么 | 用例 |
| --- | --- | --- | --- |
| ① | 前台 `fengtt1` | 可申请态 / 禁态按钮；空理由；提交暂停；重复申请；留言/记录 | S-* 抽测、P-00～P-05、P-08 |
| ② | **本节点**审核人（或 Backup） | 待办+节点页暂停审核；通过或驳回；暂停后「仅审核重启」；可选直接置暂停 | P-06～P-14、P-15～P-16 |
| ③ | 前台 `fengtt1` | 申请恢复测试 | R-01～R-03 |
| ④ | **同一**审核人 | 恢复审核通过/驳回 | R-04～R-05 |
| → | 换下一节点 | 重复 ①～④（换的是审核人，不是先把所有节点都申请一遍） | |

> **禁止**：先在架构申请、再去隐私申请、再回架构审核——会不停换登录人。
> **正确**：架构 ①～④ 全做完 → 再数据 ①～④ → …

# 二、各节点 × 不同状态 · 申请暂停（主测线）

> **核心**：同一套操作在**每个安全大节点**上扫一遍；不要只测渗透。
> **基本信息**有完整「申请暂停 → 审核 → 恢复」逻辑，须纳入。
> **终审**无申请暂停，只有关闭（2.5）。
> **闸道** G0→G1→G2→G3；**单节点闭环**（0.6）：一个节点测完所有可能再换下一节点，少换审核人。

# 三、针对自动发邮件 / 自动任务

> 依赖调度或改天数造「到点」。能触发任务则触发；否则记「等次日 10:00」或 N/A。
> 人工一律以 **邮件发送记录** 为准。

## 3.1 暂停定时提醒邮件（核心）

| 编号 | 用例标题 | 前置 | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- | --- | --- |
| E-01 | 频率点发一封 | 节点审核暂停；暂停天数落在频率点（默认 5/10/15…）；规则启用；当天非法定假 | 触发 `pauseNodeReminderExecutor` 或等 10:00 | 标题 `【PSRB】{产品名}节点暂停通知`；同项目同批 **仅 1 封** | |
| E-02 | 正文内容 | E-01 已发 | 打开正文 | 含项目编号/名称；暂停节点表（最多 5 个）；暂停天数；自动关闭倒计时=`关闭天数-最长暂停`（≥0） | |
| E-03 | 多节点只按最长算 | ≥2 节点暂停，天数不同 | 到「仅最长达点」那天触发 | 按最长天数决定是否发；正文联系人取最长节点负责人 | |
| E-04 | 最长恢复后改算次长 | 最长节点已恢复，次长仍暂停 | 再触发 | 已恢复节点不入表；按新最长判定/组文 | |
| E-05 | 非频率点不发 | 暂停天数不是 5 的倍数（如 6） | 触发 | 无新暂停通知 | |
| E-06 | 普通周六日仍发 | 频率点落在普通周末且非法定假 | 触发 | **应发送** | |
| E-07 | 法定假不发 | 法定节假日 | 触发 | **不发送** | |
| E-08 | 项目已关闭不发 | 终审/项目已关闭但仍有历史暂停数据 | 触发 | 跳过该项目 | |
| E-09 | 查看详情跳转 | 打开暂停通知点【查看详情】 | 进前台项目 **基本信息**（不是后台/终审） | |
