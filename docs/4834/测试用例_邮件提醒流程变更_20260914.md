# 说明

需求主线：Wiki/PRD《【PSRB】4834-邮件提醒流程变更相关》（工作区未检出 `prd/4834/4834prd.pdf`，以 `prd/4834/用例全集.md` 摘录的验收点为准）。代码补充：`csl-new-front`、`csl-new-ui`、`csl-new-server`。

术语：冒烟测试 = 提测后先跑的最短主链路，失败则版本不可测；回归测试 = 发布前按功能点拆开的全量用例。P0 = 核心主流程/阻塞；P1 = 重要分支；P2 = 次要与体验。

造数建议：项目名 `4834-QA-20260914-xx`；角色用前台基本信息接口人、节点介绍栏审核人/Backup、超管 `mail_reminder_manager`。节点状态码以代码为准：未开启=103、免审=101、免审(遗留漏洞)=102、审核通过=2、审批通过(遗留漏洞)=21、审核暂停/暂停测试=99、已关闭=11。

## 节点闸道（必读 · 引用公共规则）

> **全项目统一**，完整定义见 **[`docs/common/节点闸道规则.md`](../common/节点闸道规则.md)**（代码：`utils/node-order.js`）。  
> 摘要：G0 基本信息测完→审过 → G1 四节点（含前台提交+后台审核）测完→审过 → G2 五节点同理 → G3 终审才测关闭。

**冒烟最短路径**（SMOKE-*）：造数钉死**一个** `pause_ok_node`，按 **CFG → FP → BP → FR → BR → FC → BC** 跑完该节点闭环，再测终审关闭。  
**全量回归**：必须守公共闸道；按节点从左到右，**每个节点测完所有可能性再换下一节点**。

人工清单：`测试用例_人工执行_按路径归拢.md` §0.5～0.6。  
造数：`--stop-at-gate g0|g1`；`--focus-node 数据安全`（或 `PSRB_FOCUS_NODE`）钉死单节点。
