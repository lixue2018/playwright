- **步骤**：满足可编辑条件，**不选**编号，其余必填项填齐后提交

- **前置**：样本 E / N2 已有编号

- **步骤**：可编辑时改选编号或清空 → 取消/关弹窗/不点保存  
- **预期**：再次打开仍为改前值  

### TC-COM-006 保存失败不假成功

- **步骤**：（可人为制造校验失败，如其他必填缺失）带编号提交失败  
- **预期**：无成功提示；编号不写入；输入可按现流程保留重试

## 3. F-002 五类节点 — 可编辑矩阵

> 下列矩阵对 **渗透 / 架构 / 数据 / 隐私 / AI** 各跑一遍（架构·数据·隐私走 `threatenDetail`，用对应节点入口）。  
> 用例 ID 格式：`TC-{PEN|THR-ARCH|THR-DATA|THR-PRIV|AI}-F002-0x`

| 用例 | 编辑前状态 | 曾遗留 | 本次状态 | 编号控件 | 选编号保存 |
| --- | --- | --- | --- | --- | --- |
| F002-01 | 遗留 | 任意 | 已修复 | **可编辑** | 可选保存（原直修路径） |
| F002-02 | 非遗留 | **有** | 已修复 | **可编辑** | 可选保存（历史路径） |
| F002-03 | 非遗留 | **无** | 已修复 | **禁用** | 不可新增关联 |
| F002-04 | 任意 | 任意 | 非已修复 | **禁用** | 不可新增关联 |
| F002-05 | 已修复（历史） | 有（或编辑前即遗留路径满足） | 保持已修复 | **可编辑**（按代码：submit=3 且 saved=2 或 everRemained） | 允许补填/改绑 |

### 补充步骤说明

#### TC-*-F002-01 遗留 → 已修复

1. 打开样本 A，确认当前为遗留  
2. 改状态为已修复 → 编号可编辑  
3. 选 RP-PROJ 保存 → 详情回显；前台同洞回显（见第 7 节）  

#### TC-*-F002-02 曾遗留 → 已修复

1. 造数：非遗留 → 改为遗留（产生 content 以 ` -> 遗留` 结尾的日志）→ 再改为待修复等非遗留  
2. 打开样本 B，确认接口/详情带 `everRemained=true`  
3. 改为已修复 → 可编辑 → 选编号保存成功  

#### TC-*-F002-02b 日志负例（按代码）

1. 仅在留言/说明中写「遗留」，或日志为「遗留评估」且 **不以** ` -> 遗留` 结尾  
2. 编辑前非遗留、改为已修复  
3. **预期**：禁用（不计入曾遗留）  

#### TC-*-F002-03 从未遗留直接已修复

1. 样本 C → 已修复  
2. **预期**：禁用 + tip；即使前端绕过，后端 `RepairProjectLinkRules` 也不应写入  

#### TC-*-F002-04 非已修复

1. 状态为待修复/遗留/遗留评估等，不改为已修复  
2. **预期**：编号禁用  

#### TC-*-F002-05 先选编号再改回非已修复

1. 满足可编辑时选 RP-PROJ  
2. 再把本次状态改回非已修复后保存  
3. **预期**：本次新增不保存；若原先无编号则仍无；若原先有编号则仍保留（TC-COM-004）  

#### TC-*-F002-06 改绑

1. 已有 RP-PROJ，满足可编辑时改选 RP-PROJ-2 保存  
2. **预期**：回显为新编号；前后台一致  

#### TC-*-F002-07 清空提交（选填）

1. 可编辑时 clear 编号后保存  
2. **预期（按代码）**：`valueToPersist` 对 blank 返回 null → **不覆盖**已有值（即清空操作不会擦掉旧编号）。若产品期望「可显式清空」，与代码不一致时记缺陷并对照确认结论「永不自动清空 / 空不写库」。
